## 宿題

- 取り組んだレベル：発展（a）ADK で作り直す
- やったこと：
  - 同じ学習支援エージェントを Google の ADK（google-adk 2.13.0）で作った。ツールは `app/tools.py` の 3 つの関数（`search_glossary`・`get_lecture_summary`・`make_quiz`）をそのまま渡し、`INSTRUCTIONS` も同じ文面にした。モデルは同じ `gemini-3.5-flash-lite`。
  - `adk run`（コマンドライン）と `adk web`（ブラウザ）で、演習と同じ 2 つの質問「LoRAとQLoRAの違いは？」「第2回の内容から確認問題を1問出して」を試した。
  - ADK（`google-adk` 2.13.0）は、別の仮想環境に入れた。
- 結果：

| 観点 | Pydantic AI（このリポジトリ） | ADK |
|---|---|---|
| 作り方 | `Agent(instructions=...)` を作り、`agent.tool_plain(関数)` でツールを 1 つずつ登録。モデルは実行時（`run_sync`）に渡す | `Agent(name=, model=, instruction=, tools=[関数, ...])` で、モデルとツールを 1 か所で渡す。フォルダ（`__init__.py` と `agent.py`）の中に `root_agent` という名前で置く決まりで、`adk run`・`adk web` がそれを探して読み込む |
| ツールの関数 | `app/tools.py` の関数 | 同じ関数をそのまま渡せた |
| 実行方法 | `python -m app.agent` | `adk run`（コマンドライン）、`adk web`（ブラウザ） |
| ツール呼び出しの見え方 | このリポジトリの `--trace`（`app/agent.py` の `print_trace`）：ツール名・引数、戻り値は先頭 120 文字、`[usage]` に `requests` と cost | `adk run` は既定の表示では回答だけ。`--jsonl` を付けるとツール呼び出し（名前と引数）、戻り値の全文、LLM 呼び出しごとのトークン数が出る。`--verbose` ではツール呼び出しは端末に出ず、ログファイルに記録された。`adk web` の Events はツール名・引数・完了を順に表示し、ツール結果にカーソルを合わせると戻り値の全文が出る。Traces は LLM 呼び出しとツール実行の所要時間を棒グラフで表示し、Total latency も出る |

- 気づき・疑問：
  - 書き方は、大きくは変わらなかった。エージェントの定義は、どちらも数行で、ツールは普通の関数をそのまま渡せた。違いは、モデルを渡す場所（Pydantic AI は実行時、ADK は定義時）、ツールの登録の仕方（1 つずつ、またはリスト）、フォルダの決まり（ADK は `root_agent`）だった。
  - 同じ ADK でも、実行方法とオプションでツールの見え方が違った。既定の `adk run` は回答だけだった。`--jsonl` を付けると、ツール呼び出し（名前と引数）、戻り値の全文、LLM 呼び出しごとのトークン数が出た。`--verbose` では端末には出ず、ログファイルに記録された。`adk web` では画面で見られる。
  - `adk web` の Traces では、LLM の呼び出しとツールの実行それぞれの所要時間が見えた。このリポジトリの `--trace` には、時間の表示がない。
  - `--trace` は、このリポジトリに最初から入っている表示（`app/agent.py` の `print_trace`）であり、Pydantic AI 本体の機能ではない。ADK の画面や `--jsonl` はフレームワーク本体の機能なので、見え方の差には、フレームワークの差と、リポジトリ側の表示の差が混ざっている。
  - 分からなかったこと：Traces の `(merged)` が何を表すか（2 つのツール呼び出しをまとめた表示に見えるが、確認していない）。cost の確認方法（トークン数は `--jsonl` の出力に出たが、Pydantic AI の `[usage]` にある cost に当たる値は確認していない）。
